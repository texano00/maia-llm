# Maia LLM Development Setup

## Requirements

- Node.js 22 or newer
- npm 10 or newer
- Docker Desktop (or Docker Engine + Compose) for local PostgreSQL and MinIO
- Windows 10/11 x64 for the shipping desktop target

## Install

```bash
npm install
cp .env.example .env
docker compose -f infra/docker-compose.yml up -d
```

`.env` is for the telemetry backend only. Provider credentials belong in the
desktop app's OS-protected credential vault and must never be committed.

## Run

```bash
# Desktop (mock providers first)
npm run -w @maia/desktop dev
MAIA_PROVIDER_MODE=mock npm run -w @maia/desktop dev

# Telemetry API
npm run -w @maia/telemetry-api dev
```

`npm run -w @maia/desktop dev` rebuilds `better-sqlite3` for the Electron ABI
before starting. Node-based unit tests expect the Node ABI; after running the
desktop app, restore it with `npm rebuild better-sqlite3` before running
`npm test` again.

## Verify

```bash
npm run lint
npm run typecheck
npm test
npm run test:contract
npm run test:integration
```

Live GPU calls are prohibited in CI and should only be used in explicit manual
smoke tests with a low session cap.

## Installer and in-app updates

The NSIS installer detects a previous Maia LLM installation through the
`Software\<app-guid>` registry key and updates it in place. It asks for
confirmation before writing files, reuses the existing install folder (so
shortcuts, the uninstall entry and `%APPDATA%\Maia LLM` survive) and never shows
the install-mode or directory pages. The behavior lives in
`apps/desktop/resources/installer.nsh`.

The packaged app checks the GitHub Releases feed on startup and every
`MAIA_UPDATE_CHECK_INTERVAL_HOURS` (default 24). A newer version shows a banner in
the top-right corner with release notes; the user decides when to download, and
the app restarts to apply the update. `app-update.yml` is generated by
electron-builder from the `publish` section of `apps/desktop/electron-builder.yml`.

Publish a usable feed with the manual `windows-dev-build` workflow:

```bash
gh workflow run windows-dev-build.yml --ref <branch> \
  -f channel=stable -f publish_release=true
```

The job uploads `MaiaLLM-Setup-<version>-x64.exe`, its blockmap, `latest.yml` and
`SHA256SUMS.txt` to the `v<version>` release. Installed clients on an older
version will see the banner on their next check. `channel=beta` publishes a
prerelease, which is only offered to installations running with
`MAIA_RELEASE_CHANNEL=beta`.

To exercise the banner without publishing, run the desktop in development mode
with `MAIA_UPDATE_SIMULATE_VERSION=9.9.9`.

### Watching a packaged build from another machine

The telemetry API doubles as a diagnostic sink during testing. Start it so it
accepts connections from the Windows host, then launch the desktop app with
`MAIA_DIAGNOSTIC_LOG_URL` pointing at it:

```bash
# terminal 1: keep it running while you test
TELEMETRY_HOST=0.0.0.0 npm run -w @maia/telemetry-api dev
```

```powershell
# PowerShell on Windows: every app log line is mirrored to terminal 1
$env:MAIA_DIAGNOSTIC_LOG_URL = "http://localhost:8787/v1/diagnostics/logs"
Start-Process "$env:LOCALAPPDATA\Programs\Maia LLM\Maia LLM.exe"
```

The endpoint echoes events as `[diag] <time> <level> <message>`, keeps the last
1000 lines in memory, and returns them from
`GET /v1/diagnostics/logs?limit=200`. Nothing is persisted. `MAIA_UPDATE_FEED_URL`
likewise overrides the update feed when testing a mirror.
